一、需求背景

1.1 现状问题

当前项目已具备登录、图片上传、生成任务、配额、作品、支付、后台和对象存储能力，但用户端首页与生成页仍以旧信息架构为主；外部原型已经形成更明确的沉浸式视频效果浏览体验，却仍使用前端硬编码、固定三条效果、单图上传和静态 20 ✦。

现状问题本次机会
外部原型分类、效果、余额和价格均为静态演示；媒体为空；生成按钮不连接真实任务。保留视觉语言，替换为后端目录、真实上传和生成状态。
当前 H5业务能力完整，但首页和创作页与新的 Vireal 内容体验不一致。保留认证、支付、任务、作品与异常处理，仅更换用户可见界面和内容数据源。
当前管理台已有用户、内容、生成、订单和键值配置，缺少分类、效果、变体与运营媒体管理。增加独立的“效果模板管理”，让运营无需改代码即可发布内容。
当前后端AppVideoTaskCreate 仅允许 dance、单图、5/10 秒，模型和提示词写在代码中。将图片数量、时长、价格、模型和提示词收敛为服务端管理的效果配置。

1.2 为什么现在做

本次视觉基准、列表数据草案和目标代码库均已明确。先完成可运营的数据模型与 H5 迁移，可以让后续新增效果只通过管理台完成，并避免每次新增分类都重新发布前端。

1.3 范围边界

本期包含

首页与生成页视觉迁移；动态目录；默认三条缺省效果；管理台 CRUD；对象存储媒体；单/双图；动态时长、价格、模型、提示词；任务与余额联动。

本期不改变

现有登录体系、用户作品权限、支付入口、任务幂等、失败补偿、媒体清理和管理员权限模型。成人授权前后端校验暂时关闭，但保留未来恢复所需的配置能力。

关键约束：分类可见不等于效果可生成。后台发布效果前必须至少存在一个启用的生成变体，并完成模型、时长、价格和提示词配置；否则效果只能保存为草稿。

2.1 上线验收门槛

  • 六个首期分类均可从数据库读取，分类下效果数量可增减；初始迁移共创建 18 条效果。
  • 无封面、无预览视频时，首页与详情页均使用分类色调、序号和标题生成缺省视觉。
  • 后台上传的封面与预览视频能写入当前对象存储，并在 H5 生效。
  • 任意价格、时长、图片数量或启用状态变更，无需重新构建 H5。
  • 任务提交时客户端不能覆盖模型、提示词或价格；服务端以已发布变体为唯一依据。

三、用户与使用场景

手机浏览用户

在短时间内滑动分类、观看效果并挑选想体验的模板，期待页面沉浸、加载快、无破图。

生成用户

希望知道要上传几张图、需要多少金币、能生成多长，并能清楚看到排队、处理中、成功或失败。

内容运营管理员

需要上传媒体、配置模型与价格、调整排序和上下线效果，同时可追溯每次配置变更。

5.2 核心功能模块化方案

功能一：动态分类与效果目录

首页完全沿用已确认原型的视觉结构，但分类、效果数量、排序、媒体和价格摘要均由目录 API 决定。

关联 F-01 至 F-03手机 H5Focus: home

交互逻辑流程图

flowchart TD
  A[打开 H5 首页] --> B{目录请求成功}
  B -- 否 --> C{存在可用缓存}
  C -- 是 --> D[只读展示缓存并标记需刷新]
  C -- 否 --> E[展示加载失败和重试入口]
  E --> B
  B -- 是 --> F[按后台排序展示启用分类]
  F --> G{分类有已发布效果}
  G -- 否 --> H[公共目录隐藏该分类]
  G -- 是 --> I[渲染任意数量效果]
  I --> J{封面或预览可用}
  J -- 是 --> K[展示真实媒体]
  J -- 否 --> L[展示色调编号标题缺省卡片]
  K --> M[用户选择效果]
  L --> M
  M --> N[进入效果生成页]

详细规则

  • 排序：分类和效果均按 sort_order ASC, created_at ASC。
  • 数量：前端不假设固定三条；新分类仅在创建时由后端默认生成三条效果，之后可任意增删排序。
  • 媒体降级：预览视频失败后退化为封面，封面为空或失败后使用分类 tones、序号和标题绘制已确认的缺省卡片。
  • 空分类：公共目录隐藏没有已发布效果的分类；管理台仍显示并提示运营补充内容。
  • 失败恢复：目录请求失败时不回退到代码硬编码；有缓存则只读展示并标记，完全无数据时展示重试。

详细规则

  • 图片数量：input_image_count 仅允许 1 或 2；kiss、romance 的种子数据为 2，其他种子数据为 1。
  • 上传：每张图片独立上传并返回 upload_id；失败仅重试对应槽位，成功素材保留在当前页面。
  • 变体：时长选项来自启用的 effect variant；禁用时长不允许提交。
  • 价格：客户端只展示服务端价格，不提交 coin_cost、model 或 prompt，防止篡改。
  • 提交：请求仅包含 effect_id、variant_id、upload_ids 和 Idempotency-Key；重复提交返回同一任务。
成人授权校验：本期前端不展示，服务端不阻断，任务请求不要求 consent；配置和历史字段保留，以便后续恢复。

功能三：任务状态、失败补偿与作品

生成任务在服务端持久化；用户可以离开页面，重新进入后通过任务 ID 恢复状态，不产生重复扣费。

  participant U as 用户 H5
  participant A as 应用 API
  participant D as PostgreSQL
  participant Q as 生成队列
  participant M as 模型服务
  participant S as 对象存储

  A->>D: 校验配置配额余额并创建任务快照
  D-->>A: 返回任务和扣费结果
  A-->>U: 返回 queued 和最新余额额度
  A->>Q: 投递生成任务
  Q->>M: 使用服务端模型和提示词执行
  alt 生成成功
    M-->>Q: 返回视频结果
    Q->>S: 写入生成视频
    Q->>D: 更新 succeeded 和结果对象
    U->>A: 轮询任务
    A-->>U: 返回播放地址和最新余额额度
  else 生成失败
    M-->>Q: 返回错误
    Q->>D: 更新 failed 并执行退款补偿
    U->>A: 轮询任务
    A-->>U: 返回失败原因和退款结果
  end
  Note over U,A: 网络中断后使用任务 ID 恢复轮询

详细规则

  • 任务快照：保存效果、变体、价格、模型、prompt_version 和实际执行 provider，避免运营修改影响历史任务。
  • 状态：至少包含 queued、processing、succeeded、failed；客户端根据服务端状态渲染，不自行推断完成。
  • 断线：任务 ID 写入会话恢复点；网络恢复后继续轮询，禁止自动重新创建。
  • 失败：模型失败记录可审计错误码并执行退款或补偿，H5 展示可理解原因和重试入口。
  • 作品：成功结果进入作品列表；无作品时展示已确认空状态并引导返回发现页。

  D --> E[维护双语名称图片数排序和推荐]
  E --> F[配置时长金币模型和提示词]
  F --> G{上传封面或预览视频}
  G -- 是 --> H[媒体写入当前对象存储]
  H --> I{媒体校验成功}
  I -- 否 --> J[保留旧媒体并提示重试]
  J --> G
  I -- 是 --> K[保存媒体资产记录]
  G -- 否 --> L[继续使用缺省媒体视觉]
  K --> M[执行发布校验]
  L --> M
  M --> N{存在启用变体且配置有效}
  N -- 否 --> O[阻止发布并显示字段错误]
  N -- 是 --> P[发布目录数据并写入审计日志]
  P --> Q[H5 下次目录请求动态生效]

详细规则

  • 分类：维护双语名称、slug、色调、排序和启停；创建分类和三条缺省效果必须同事务。
  • 效果：维护名称、描述、图片数量、排序、推荐关系、发布状态和任意数量变体。
  • 媒体：封面和预览直接上传当前对象存储，使用独立目录和长期资产策略，不套用用户素材 24 小时过期规则。
  • 发布校验：至少一个启用变体；图片数量为 1 或 2；时长价格有效；模型和提示词完整。
  • 审计：创建、编辑、排序、启停、发布、媒体替换和删除均记录管理员与变更摘要。

5.3 公共 API

方法路径用途服务端约束
GET/api/v1/app/effect-catalog一次返回已发布分类、效果摘要与可选变体。不返回生成提示词、存储对象 Key 或内部模型密钥；支持 ETag/短缓存。

GET/api/v1/app/video-tasks/{id}轮询任务和取得播放地址。只能访问本人任务；返回最新余额/额度摘要。

七、异常与边界处理

场景服务端行为H5 / 管理台反馈
目录请求失败返回明确错误码，不回退到过期硬编码目录。保留品牌页骨架，显示重试；已缓存目录可标记后只读展示。
分类无已发布效果公共目录过滤该分类。管理台显示空分类警告。
媒体为空或加载失败效果数据仍可返回。按 tones + 序号 + 标题显示缺省视觉。
效果或变体已下线创建任务返回 409，不按旧缓存继续提交。提示“效果已更新”，刷新详情并推荐其他效果。
图片数量不匹配422；任务不创建、不扣费。定位缺少的图片槽位。
余额不足409；任务不创建。展示所需金币与当前余额，进入现有充值入口。
重复提交同用户 + Idempotency-Key 返回同一任务。按钮进入提交中，不产生第二次扣费。
模型配置无效后台禁止发布；运行时仍异常则任务失败并按现有规则补偿。管理员看到字段级错误；用户看到可理解的失败提示。
运营媒体上传失败不写入有效资产记录；清理孤立对象。保留原媒体，允许重试。
网络中断任务状态保存在服务端。恢复后使用任务 ID 继续轮询。
