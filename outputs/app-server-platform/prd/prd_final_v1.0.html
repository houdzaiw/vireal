App 服务端与后台管理系统 PRD v1.0

本 PRD 定义第一版本地/内网可运行的 FastAPI 服务端与 React 后台管理系统，覆盖移动 App 设备号登录、头像昵称、文字/图片动态、本地图片存储、Apple IAP 与 Google Play 支付回调、后台治理和 key-value 运营配置。

技术底座基于 FastAPI Full-Stack Template 二次开发，保留 FastAPI、PostgreSQL、Docker Compose、React 后台和管理端登录基础能力。
项目拆分server 承载后端和后台管理；移动 App 单独项目，只调用服务端 API。
账号体系后台管理员使用账号密码登录；App 用户使用设备 UUID 登录，两者完全独立，不共用用户表。
第一版原则本地/内网先跑通闭环，优先保证核心功能可用，暂不做复杂权限、多租户、内容审核和对象存储。

一、需求背景

项目需要为移动 App 提供一套能快速开发、便于本地/内网验证的服务端 API，同时需要一个后台管理系统用于查看和处理 App 用户、用户生成内容、支付订单状态以及简单运营配置。开发者具备 Python 开发能力，适合基于成熟 FastAPI 模板进行二次开发，避免重复搭建登录、数据库、Docker、前后端联调、API 文档和测试基础设施。

当前阶段的核心诉求不是构建复杂业务中台，而是快速形成一个可验证闭环：App 用户无需注册账号即可通过设备号进入，能够修改头像昵称、发布文字/图片动态；后台能够查看并处理用户和内容；服务端能够接收 Apple IAP 与 Google Play 支付通知；运营配置能够由后台维护，并在 App 启动时下发。

为什么现在做

  • 移动 App 需要尽快进入可用验证阶段，设备号登录能降低首版进入门槛。
  • 动态内容与图片上传需要服务端闭环，否则无法验证内容流体验。
  • 订单状态必须由后端记录，避免只依赖客户端支付结果导致状态不一致。
  • 后台管理必须在首版存在，否则用户禁用、内容删除、配置调整和订单排查无法闭环。

技术选型结论

使用 FastAPI Full-Stack Template 二次开发合理，但应把它定位为“服务端 + 后台管理系统底座”。移动 App 不放进该项目，单独维护，只通过 API 与后端通信。模板原用户体系建议保留给后台管理员；App 用户使用独立表和独立 token 机制。

表名 用途 核心字段 备注

功能 1：App 设备号登录与启动配置

App 首次打开时通过设备 UUID 建立用户身份，登录成功后拉取启用配置并进入动态流。

P0

交互流程图

flowchart TD
  A["App 启动"] --> B["读取本机设备 UUID"]
  B --> C{"设备 UUID 是否存在"}
  C -- "不存在" --> C1["生成本机设备 UUID"]
  C -- "存在" --> D["请求设备号登录接口"]
  C1 --> D
  D --> E{"网络是否正常"}
  E -- "否" --> E1["展示网络异常提示"]

  E -- "是" --> F["服务端校验设备 UUID"]
  F --> G{"设备是否已绑定 App 用户"}
  G -- "否" --> H["创建 App 用户"]
  H --> I["创建设备绑定记录"]
  G -- "是" --> J["更新最近登录时间"]
  I --> K["签发长期 App token"]
  J --> K
  K --> L["返回用户资料和 token"]
  L --> M["App 拉取启动配置"]
  M --> N{"配置接口是否成功"}
  N -- "否" --> N1["使用本地默认配置"]
  N -- "是" --> O["缓存启用配置"]

  N1 --> P

规则描述

  • 触发条件：App 启动且本地没有有效 App token，或用户主动退出后重新进入。
  • 身份规则：设备 UUID 对应一个 App 用户；设备 UUID 变化即创建新用户，不提供找回。
  • 返回内容：App 用户 ID、昵称、头像、状态、长期 token、最近登录时间。
  • 异常处理：设备 UUID 缺失返回参数错误；网络失败时展示提示并保留本地默认配置。

功能 5：Apple IAP 与 Google Play 支付回调

后端接收平台通知，记录事件，幂等处理重复通知，并更新订单状态供后台排查。

P0

交互流程图

flowchart TD
  A["App 发起平台支付"] --> B["Apple 或 Google 返回客户端结果"]
  B --> C["客户端可请求订单同步"]
  A --> D["平台发送支付通知到后端"]
  D --> E{"通知来源是否可识别"}
  E -- "否" --> E1["记录异常通知"]
  E -- "是" --> F["解析平台交易号和商品 ID"]
  F --> G{"事件是否已处理"}
  G -- "是" --> G1["返回幂等成功"]
  G -- "否" --> H["写入支付事件记录"]
  H --> I{"能否匹配订单"}
  I -- "否" --> I1["记录待排查事件"]
  I1 --> I2["后台订单页展示异常"]
  I -- "是" --> J["更新订单状态"]
  J --> K{"状态是否支付成功"}
  K -- "否" --> K1["记录失败或取消状态"]
  K -- "是" --> L["记录支付成功时间"]
  L --> M["后台订单页展示已支付"]
  K1 --> N["后台订单页展示最新状态"]

规则描述

  • 触发条件：Apple 或 Google 向服务端 webhook 推送支付状态变化。
  • 事件记录：保存平台、交易号、商品 ID、事件类型、处理结果和错误信息。
  • 幂等处理：按平台事件 ID 或交易号识别重复通知，重复事件直接返回成功。
  • 第一版边界：本地/内网可先使用模拟通知跑通流程；生产接入时补齐签名校验和平台 API 二次校验。

功能 6：key-value 运营配置

后台维护简单 key-value 配置，App 启动时请求配置接口并缓存所有启用配置。

P0

交互流程图

flowchart TD
  A["管理员进入运营配置页"] --> B["新增或编辑 key value 配置"]
  B --> C{"key 是否唯一"}
  C -- "否" --> C1["提示 key 已存在"]
  C -- "是" --> D["保存配置值和说明"]
  D --> E{"是否启用配置"}
  E -- "否" --> F["配置不对 App 下发"]
  E -- "是" --> G["配置进入启用集合"]
  G --> H["App 启动后请求配置接口"]
  F --> H
  H --> I{"配置接口是否成功"}
  I -- "否" --> I1["App 使用默认配置"]
  I -- "是" --> J["服务端读取启用配置"]
  J --> K["返回 key value 对象"]
  K --> L["App 缓存配置并应用"]
  A --> M["管理员停用配置"]
  M --> N["更新启用状态为关闭"]
  N --> O["下次启动不再返回该 key"]

规则描述

  • 触发条件：管理员新增、编辑、启用或停用配置；App 启动时请求配置接口。
  • key 规则：全局唯一，不允许重复；建议只允许字母、数字和下划线。
  • 下发规则：只下发启用配置；停用配置不返回给 App。
  • 第一版边界：不做灰度、不做版本控制、不按地区、App 版本或用户分组下发。

七、异常与边界处理

场景 处理规则 第一版要求
设备 UUID 为空或格式异常拒绝登录，返回明确错误码和错误信息。必须处理
设备 UUID 变化视为新设备和新用户，不做账号找回。必须处理
App 用户被禁用禁止发布动态；资料接口返回用户状态，App 端拦截。必须处理
图片上传失败返回失败原因；不创建依赖该图片的动态。必须处理
图片类型或大小不合法限制为常见图片类型，并设置大小上限。必须处理
动态已删除App 列表和详情不返回，不显示占位。必须处理
禁用用户历史内容默认从动态流过滤，后台保留记录。必须处理
支付通知重复按平台事件 ID 或交易号做幂等处理。建议处理
支付通知无法匹配订单记录异常事件，后台可查看。建议处理
配置为空配置接口返回空对象，App 使用默认值。必须处理
后台误删内容使用软删除，数据库保留记录，第一版不提供恢复入口。建议处理
后台无权限或 token 过期跳转登录页或展示登录失效提示。必须处理

八、数据追踪与埋点

第一版以服务端业务日志和数据库事件记录为主，不强制接入第三方埋点平台。

事件 触发时机 关键字段
app_device_login设备号登录成功或失败app_user_id、device_uuid_hash、platform、result、error_code
profile_updated头像或昵称修改成功app_user_id、changed_fields、updated_at
content_created动态发布成功content_id、app_user_id、image_count、text_length
content_deleted_by_admin后台删除动态content_id、admin_user_id、deleted_at
app_user_disabled_by_admin后台禁用用户app_user_id、admin_user_id、reason、updated_at
payment_event_received收到 Apple/Google 支付通知platform、transaction_id、event_type、process_result
config_changed后台新增、修改、启停配置config_key、admin_user_id、change_type、updated_at
