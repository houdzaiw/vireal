## 建议开发顺序

```text
M0 -> M1 -> M2 -> M3 -> M4 -> M6 -> M5 -> M7 -> M8
```

原因：

- 先跑通身份、上传和动态，App 端主链路最快可验证。
- 配置模块简单，可以在支付前完成，增强后台闭环。
- 支付回调对生产环境依赖较多，第一版可先用模拟通知接入。
- 后台前端最后整合，避免 API 尚不稳定时频繁返工。
